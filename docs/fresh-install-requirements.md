## R1 [P1] 核心界面依赖 Array.prototype.at，与 macOS 12.0 的承诺冲突

**位置**

- `src/lib/components/StatusPanel.svelte:31`
- `src/lib/components/ChatPanel.svelte:61`、同文件模板中的 messages.at 调用
- `src/lib/components/DialogBox.svelte:16`
- `src/lib/components/MeshFace.svelte:4` 的兼容性检查
- `vite.config.ts` 的 `safari13` target；`tauri.conf.json` 的 `minimumSystemVersion: "12.0"`

**问题与证据**

头像组件检查 `.at` 等 API 后可以降级，但核心聊天和状态组件仍无保护地调用 `.at(-1)`。这些组件不因头像降级而获得兼容性。

WebKit 官方说明 Safari 15.4 才增加 `at()` 支持；该版本随 Monterey 12.3 提供。不能把 macOS 12.0 的旧 WebKit 当成必然具备此 API：[WebKit 发布说明](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)。

本轮取当前 StatusPanel 的真实表达式，用项目 esbuild 的 `target: safari13` 转换，输出仍保留 `.at()`；在移除该 API 的隔离 JS 环境中得到 `TypeError: steps.at is not a function`。这是业务表达式级复现，未在真实 macOS 12.0 上运行整个 UI。

**要求**

优先保留现有支持范围：替换核心组件中的调用，或在所有使用它的模块执行前提供可靠兼容层。检查其他业务/依赖 API，不能只修头像。若决定提高最低系统要求，必须同步 bundle、所有安装文档及兼容说明，并以实际验证版本为准，不能只修改一句 README。

**通过标准**

在缺少 `.at` 的环境中，主界面、展开聊天、安装状态、错误提示和设置入口均能使用；头像正常降级。仍声明支持 macOS 12.0 时，需要对应 WebKit 的实际验收证据，不能用现代 Node 或单纯构建成功替代。

## R2 [P1] 录音 worker 可能先于 DAEMON 发布而永久退出

**位置**：`src-tauri/src/voice/record.rs::prewarm()`（约 311–322 行）、`daemon_loop()`（约 407–410 行）。

**问题与证据**

`prewarm()` 先 spawn 线程，后执行 `DAEMON.get_or_init()`；worker 一开始读取 DAEMON，若还不存在就直接 return。合法调度下，worker 可以先运行并退出，主线程随后保存一个 receiver 已断开的 daemon。后续 `prewarm()` 又因 DAEMON 已存在直接返回，不能恢复。

本轮将原样的 prewarm 函数放入临时 Rust harness，模拟音频设备，在共享状态发布前加入调度延迟以强制该合法交错。worker 保留原始入口判断。得到：

```text
worker_exited_before_publication=true
daemon_published=true receiver_disconnected=true
```

这是确定性调度模型验证，不是真实麦克风实测，不表示每次启动都会发生。

**要求**

在 worker 使用之前完成共享状态发布，或用明确的启动握手保证顺序。处理线程启动失败/worker 已退出时的错误状态。**保留麦克风预热与现有 capture owner / gate 语义**，不能通过删除预热来掩盖竞态。

没有输入设备、权限拒绝或设备初始化失败时，至少向用户给出实际原因及可执行的恢复步骤；不强制要求实现麦克风热插拔或权限自动修复。

**通过标准**

强制 worker 先获调度也不能读到未初始化状态；不会保留“看似已初始化但 receiver 已断开”的状态。正常录音开始/停止、取消、打断和首段音频预热行为均不回归。真实麦克风权限按验收矩阵测试。

## R3 [P2] 中断后只剩解释器、缺少 pip 的 venv 无法靠重启恢复

**位置**：`src-tauri/src/voice/venv.rs::ensure_venv()`，约 278–335 行。

**问题与证据**

程序只在 `venv/bin/python3` 不存在时创建 venv。若创建阶段中断，解释器已存在但 pip 尚未完成，重启会跳过创建；`python -m pip` 失败被当作非致命，随后执行不存在的 `venv/bin/pip` 再失败。界面却提示检查网络后重启自动重试。

本轮在临时目录构造缺少 pip 的环境，运行当前原样 ensure_venv 主逻辑（仅替换用户目录、窗口/事件接口为测试依赖）。连续两次均得到 `spawn failed: No such file or directory`，第二次没有重新创建或修复。没有改动真实用户目录，也没有连接 PyPI。

**要求**

复用环境前验证解释器可执行及 pip 可用性。对半创建环境执行安全修复/重建，或明确显示“环境不完整”的定向恢复办法。若保留自动重试承诺，就必须保证重启能够实际进展；不能把本地 pip 缺失统称为网络错误。

操作范围仅限 PA 自有 venv 和相关 marker；保留配置、数据库、用户头像、已注册声纹及模型缓存。

**通过标准**

覆盖解释器缺失、解释器存在但缺 pip、缺依赖/安装中断、marker 残留。环境恢复后可启动语音服务；若需用户手动恢复，界面说明与实际步骤一致，执行后能成功。不能让用户陷入重复重启。

## R4 [P2] 打包版配置来源与文档不一致，可能连错网关

**位置**：`src-tauri/src/lib.rs:14–20`；README Route B 配置与终端排错步骤；`.env.example`。

**问题与证据**

当前开发版和打包版都先 `dotenvy::dotenv()`，再读取 `~/.pocket-agent/.env`；默认加载不会覆盖已经存在的环境值。故进程环境优先，cwd 或父目录 .env 次之，用户目录 .env 最后补缺。

README 却写打包版读取用户目录配置、而不是仓库 .env。用户先源码试用，再在仓库终端里运行打包版排错时，可能继续使用开发网关地址和密钥。

本轮以项目相同 dotenvy 加载方式验证：先载入 dev.env，再载入 app.env，最终 API_SERVER 仍为开发值。该测试验证配置优先级，不是对完整 .app 的 GUI 实测。

**要求**

明确且统一配置契约。推荐开发版读取项目 .env、打包版读取用户目录 .env；进程环境覆盖是否保留需明确说明。若选择保留当前加载顺序，文档必须准确给出 cwd/父目录与进程环境的优先级，并提供不会误连的打包运行方式。不能同时承诺“只读用户配置”却保留 cwd 优先行为。

缺文件、语法错误和认证失败应有可定位的诊断；诊断只能暴露配置来源及脱敏后的目标，不得打印完整密钥。

**通过标准**

开发版与打包版分别从仓库目录、无关目录启动；同时存在项目和用户配置、存在进程环境覆盖时，目标网关和认证来源均与文档一致。两种模式仅有一个配置文件时照常工作。

## R5 [P2] STT 子进程回退忽略 STT_MODEL，且没有执行时限或取消

**位置**：`src-tauri/resources/stt-helper:24`；`src-tauri/src/voice/stt.rs::transcribe_subprocess()`，约 225–262 行。

**问题与证据**

常驻服务使用配置模型（默认 base），回退 helper 却固定 `WhisperModel("tiny")`。如果用户缓存了 base/small，服务异常后切到 helper，可能突然尝试下载从未缓存的 tiny；离线时原本可用的本地模型也没有被复用。

本轮执行当前 helper，注入假的 faster_whisper 以记录模型参数，设置 `STT_MODEL=small`，实际仍得到 `actual_model=tiny`。没有下载或调用真实模型。

Rust 回退路径同步读取 stderr、等待进程，没有超时或取消检查。Python 模型加载/下载卡住时，HTTP 请求的 30 秒超时并不能限制后续这个独立子进程。

**要求**

回退遵循相同模型配置及合理的语言处理契约；若有意降级为 tiny，必须明确告知并避免意外依赖未缓存模型。为回退子进程增加可控的超时/取消与退出清理；区分首次下载等待和普通转写时限，不要求盲目统一成 30 秒。

**通过标准**

已有 base/small 缓存、tiny 无缓存、常驻服务不可用时，回退按约定运行，不无提示地改模型。模拟 helper 卡住/取消时能退出并释放录音流程，能够开始下一轮，不遗留自有进程或半成品音频。

## R6 [P2] 端口检查工具执行失败被当成“端口空闲”

**位置**：`scripts/clear-dev-port.js::run()`，约 9–14 行。

**问题与证据**

现在不再停止任何进程，旧 E1/E2 已解决。但 run() 把所有 execFileSync 异常都转换为空字符串；lsof 不在 PATH、工具执行失败与“正常查询没有监听者”无法区分。检查会返回 0，继续启动 Vite。

本轮对当前脚本做 VM 隔离执行，让 lsof 抛 `ENOENT`，结果 `missing_lsof_exit_code=0`。这是失败分支验证，没有更改系统工具或真实端口。

**要求**

区分“查询成功/正常无匹配”和“无法执行/检查失败”；无法确认时提供明确诊断并非零退出。macOS 可使用已知系统工具路径，或可靠的独立端口探测。ps 仅用于补充进程名称，其失败不应掩盖已知占用。继续保留“不自动停止进程”。

**通过标准**

覆盖空闲、IPv4-only / IPv6-only 占用、工具找不到、工具异常、只查到 PID 但拿不到命令名。已知占用或检查未知时不静默放行；空闲时可正常开发启动。

## R7 文档与交付承诺收尾（必做，不要求重写全部文档）

1. **统一真实支持范围**：README / README_AGENTS / bundle 的系统范围与 R1 最终方案一致。CLT Python 验证应写清支持区间 3.9–3.12，不能一处写“3.9 or newer”而错误恢复只要求重复安装同一 CLT。对 Intel、旧 macOS、其他 Python 组合区分已实测与未实测。
2. **明确持续联网依赖**：安装需 PyPI、HuggingFace 和可选 GitHub 下载；日常 TTS 使用 Microsoft 在线服务，Hermes 的模型是否联网取决于用户后端。将 TTS 网络失败与本地 STT 分开排查，不暗示模型缓存后整个语音系统都离线。参考 [edge-tts 官方说明](https://github.com/rany2/edge-tts)。
3. **配置与恢复一致**：按 R3/R4/R5 更新最近的 README、Agent 指南与 `.env.example`；重装/排错步骤先保留已有配置，不无条件覆盖用户密钥与网关设置。
4. **权限提示一致**：Info.plist 中“按住 fn 键说话”仍与当前 RightShift 按一次开始/再按一次停止不符。使用不依赖具体自定义键的描述，或与默认行为一致的说明。
5. **基础与可选功能分开**：基础交付是文字、按键转写、播报、打断；唤醒/声纹、电脑控制、手机端分别验收。Hermes 版本特定补丁和调优不能变成不加说明的基础必选项。
6. **交付一份验证记录**：写明最终 commit/未提交内容、系统/架构/Python/Node/Rust/Hermes 版本、执行命令、结果和未覆盖项。不要仅写“全部通过”，也不要把修改 HOME 的隔离运行称为从未安装依赖的全新 Mac。

## 建议改进：可单独排期，不作为本轮新增阻断

- **O1：可选本地 API 的失败可见性。** `api/server.rs` 在 bind 前打印 listening，8650 绑定失败只写日志。建议在实际绑定成功后输出 listening，并向设置/状态页提示手机/MCP/push 不可用；不要求因此阻止基础桌面聊天。

- **O3：启动诊断与有限恢复。** 建议提供只读诊断（配置来源、端口、解释器版本、依赖/模型状态）及用户触发的语音服务重试。安装进度、无效模型、磁盘/权限、网络失败应能区分；不强制本轮建设完整 onboarding、自动更新或后台守护。
