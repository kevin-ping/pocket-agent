# Pocket Agent v0.3.0

**Release Date**: TBD

First release since v0.2.8 (2026-06-11). v0.2.9 was never released, so everything built since v0.2.8 ships here: a phone terminal, PA as a pure relay for Hermes, background subagents, the local wake word engine, the mesh 3D avatar, a fresh-install overhaul, and the July–August voice and settings work listed at the end.

## Highlights

- **Phone terminal (experimental)** — a phone can run PA's voice and UI over the local network, with camera and device-switch tools for Hermes, and an Android shell app.
- **PA is a relay** — PA states facts and forwards Hermes' approvals and replies as they are; Hermes decides how to use the computer.
- **Background subagents** — long research goes to a Hermes subagent; PA reports the result when it is done.
- **Local wake word** — sherpa-onnx keyword spotting with an optional owner-only voiceprint gate.
- **Mesh 3D avatar** — emotion expressions, per-sentence lip sync, and per-state background colours.
- **Fresh install** — first launch on a clean Mac sets up the voice environment by itself and says how to recover when it cannot.

## Phone terminal (experimental)

- PA's local server gains `/audio` (WebSocket, 16 kHz PCM up, mp3 sentences down) and `/ui/` + `/ui/ws` (the phone runs PA's own frontend). While the phone drives, wake word, continuous conversation and barge-in use phone audio; the Mac keeps its mic and speaker closed and its window hidden.
- Both sockets require `?token=API_SERVER_KEY` and refuse everything when no key is set; `/ui/ws` accepts whitelisted commands from one client at a time.
- `/mcp`: a minimal MCP server for Hermes (bearer auth, 64 KB body cap) with `phone_camera_open` / `phone_camera_snapshot` / `phone_camera_close` and `switch_device`. Switching runs only after the turn ends and the reply has been spoken.
- Portrait phone layout: half-body avatar with state gradient, swipeable conversation / tools pages, camera preview with flip, a standby page when the computer drives, and a "move to the computer" button (tap twice within 3 s).
- `android/`: Kotlin WebView shell (minSdk 30) with a foreground audio service and CameraX preview. Not in any store: build the debug APK and install it over adb.
- `scripts/phone_sim.py` plays the phone's part from a WAV file for testing.

## Hermes integration

- **Relay, not router**: the local semantic routing pass is gone. `COMPUTER_HINT` states facts only; approvals forward every choice Hermes offers (including session / always) and still reject choices it did not offer, replays and cross-run use.
- Cancelled approvals stay dead; partial results inside `run.failed` are relayed. Session-authority approvals (`prompt_id` + `execution_generation`) are answered in the shape the run used, and unanswered approvals can be fetched again by a frontend that mounts later.
- **Subagents**: UI turns carry `DELEGATE_HINT`, so research likely to take more than a minute goes to `delegate_task`. While one is out PA polls the session every 15 s and starts a silent reporting turn when it completes. The status strip shows a yellow breathing dot while subagents run.
- **Status**: the status strip shows "Working · m:ss · N steps" during a turn, and PA says it is still working after 45 s of silence (at most every 90 s). Context compaction shows "正在整理之前的对话" (needs the local `/v1/runs` patch in HERMES.md).
- **Reasoning panel** (Settings → General → Show reasoning, off by default) shows one reasoning segment at a time; streamed reasoning needs the local `/v1/runs` patch.
- Tool previews: the status panel shows "🔧 tool: first ~60 chars"; text Hermes says before a tool call is spoken right away.
- `skills/pocket-agent/SKILL.md` for Hermes, and HERMES.md for the gateway settings PA relies on (compression thresholds, a faster summary model on MiniMax, the agent cursor, `scripts/hermes-latency.py`).
- Leave `API_AGENT` empty with Hermes so PA uses `/v1/runs`: chat completions has no stop command, and an interrupted turn keeps running.

## Wake word and voice

- Wake word is now local keyword spotting (sherpa-onnx) in a resident voice service on :8651 that also keeps Whisper, Silero VAD and the speaker model loaded. `/speaker/*` and `/kws/*` need a bearer token and the Tauri webview origin.
- Optional owner-only voiceprint gate for wake and for each utterance in continuous conversation (fail-closed).
- Wake errors are structured and shown in all 7 languages; a failed wake start no longer rolls back the whole settings save. Late arm / disarm results can no longer reopen the mic.
- Interruption needs the wake word; conversation and audio lifecycle fixes (queued audio stops with the session, barge-in arms only after playback starts).
- Short quiet utterances flush on pause; edge-tts retries once, times out after 15 s, and PA prefers the venv's edge-tts (>= 7.3.1), fixing the 403.
- Markdown is stripped before speech (the chat box still renders it); the voice hint talks like a friend.
- The recognised speech shows in an STT panel; the chat input row is replaced by a status strip (computer tools, subagents, speech detection).

## Avatar and UI

- Mesh 3D avatar with emotion expressions and per-sentence lip sync; the mouth also moves with status speech, and the avatar leaves SPEAKING when speech ends mid-turn.
- Per-state avatar background colours (Settings → Avatar, with "Restore defaults").
- On macOS 12 the mesh avatar is masked to its circle; the main window is no longer resizable; panel spacing fixes.

## Install and first launch

- The packaged .app finds its voice resources under `Contents/Resources/resources/`.
- The main window appears as soon as voice setup starts, fails or is slow; the status panel shows install stages, pip errors with a network / proxy hint, and how to recover. Setup state survives a frontend that subscribes late.
- The voice venv only uses Python 3.9–3.12, repairs a venv without pip or with a broken interpreter, and keeps an old working install when a dependency update fails offline.
- The packaged app reads `~/.pocket-agent/.env`; a dev build reads the repository `.env` first; `[config]` logs the source, and gateway errors name it.
- The dev port check tells free / busy / unknown apart; the UI avoids Safari 15.4+ APIs so it runs on macOS 12.
- README / README_AGENTS: Hermes from scratch, supported systems, network use, config location, recovery. OpenClaw is no longer supported.

## Security and privacy

- Legacy local command execution is removed.
- A real gateway key was removed from `releases/0.2.1.md`. It remains in git history: **rotate any gateway key that was in use before this release.**
- Personal names and profile names are replaced with placeholders in docs and tests.

## Upgrading from v0.2.8

- Run `npm install` after pulling: v0.3.0 adds npm dependencies (e.g. `mesh-avatar-element`); without it vite fails with `Failed to resolve import`.
- The Python voice environment in `~/.pocket-agent/venv` is checked and updated on launch.
- Set `API_AGENT` empty if you use Hermes (see above); `WAKE_STT_MODEL` / `WAKE_LANGUAGE` are no longer used.

## Known issues

- **macOS older than 13.4**: wake word and voiceprint are unavailable. The sherpa-onnx 1.12.26 wheel loads an onnxruntime that needs macOS 13.4, and the compat download PA tries returns 404. Planned fix for v0.3.1: install sherpa-onnx 1.10.46 on these systems.

## July–August 2026 changes

### Wake-word accuracy (techniques borrowed from 白龙马 / BaiLongma)

#### Step 1: Whisper hallucination filtering
- **Hallucination word bank** — 30 common Whisper hallucination fragments (Chinese + English), including video platform catchphrases ("字幕", "感谢观看", "amara.org", etc.)
- **6 filter rules** — pure punctuation, single-char, known fragment match, single-char repetition (≥5 chars, ≤2 unique), timestamp/digit patterns, phrase-level repetition
- **Wake transcription only** — filter applies to `_transcribe_for_wake()` only; `/transcribe` conversation pipeline is untouched

#### Step 2: VAD threshold tuning
- **Rust energy-VAD onset threshold** 0.015 → 0.010 — catches quieter wake words
- **Threshold cap** 0.03 → 0.02 — maintains sensitivity in moderate noise
- **Utterance peak gate** (new) — `MIN_UTTERANCE_PEAK_RMS=0.015`: buffers with peak RMS below threshold are discarded before sending HTTP, filtering noise that passes onset detection
- **Minimum send duration** 0.8s → 0.5s — "星引" (~0.5s) no longer truncated
- **Silero VAD threshold** (Python wake/check) 0.7 → 0.5 — shorter wake words no longer rejected as non-speech

### Bug fixes (post-release testing)

#### STT server VAD pre-check crash — missing audio backend
`torchaudio>=2.1` macOS wheels ship no built-in audio decode backend. Without an
explicit `soundfile` dependency, `silero-vad`'s `read_audio()` failed with
`Couldn't find appropriate backend to handle uri ... and format None`, logged on
every `/transcribe` call and silently breaking VAD-gated silence detection
(`/vad/check`) and wake-word confirmation (`/wake/check`) — both always fell back
to "no speech detected".
- **Fix**: added `soundfile>=0.12.1` to `requirements-stt.txt`.

#### Chat text streaming fell behind — and then skipped content — during TTS playback
The chat panel's per-character typewriter runs at a fixed ms/char pace unrelated
to real TTS speech duration, so on longer replies the displayed text could still
be mid-sentence after PA finished speaking.
- **Fix**: on `chat-audio-done`, immediately flush any buffered typewriter text
  (`chatStore.finishTypewriterNow()`) so text never lags behind audio.

That flush exposed a deeper backend bug: for multi-sentence replies,
`chat-audio-done` fired once per *sentence* instead of once per *turn* — the
"is this the last audio" check keyed off a `generation` value shared by every
sentence in the turn, so it was true after each one. Combined with the
unconditional flush above, this fragmented long replies: the chat box showed the
first sentence, then jumped straight to the last few words, dropping everything
in between. It also meant `notify_conversation_tts_done` (continuous-conversation
mode) could fire after just the first sentence.
- **Fix**: replaced the generation-based check with an explicit non-silent-sentence
  counter (`PENDING_NON_SILENT` + `SUBMISSION_DONE`, dedup'd via
  `AUDIO_DONE_EMITTED_GEN`) so `chat-audio-done` fires exactly once, when the true
  last sentence of the turn finishes playing.

#### Files changed
- `src-tauri/resources/requirements-stt.txt` — added `soundfile>=0.12.1`
- `src-tauri/src/commands/chat.rs` — replaced `LAST_NON_SILENT_GEN` with
  `PENDING_NON_SILENT` / `SUBMISSION_DONE` / `AUDIO_DONE_EMITTED_GEN` +
  `begin_audio_submission()` / `maybe_emit_audio_done()` helpers; wired through

### Barge-in pre-roll buffer (from Hermes 0.20.0)

#### Problem
When the user interrupted PA mid-speech, the first few words were lost —
the RMS-based detector needed 350ms of sustained audio before firing, by
which point the opening syllable was gone.

#### Fix
Added a pre-roll ring buffer (`VecDeque<Vec<i16>>`) in the Speaking branch
of the conversation state machine. Audio is continuously captured during
TTS playback; on barge-in trigger, the buffered audio is drained into the
utterance buffer so the user's first words are preserved.

- Max buffer duration: 500ms (`BARGE_IN_PREROLL_MAX_MS`)
- Memory overhead: ~48KB (16kHz mono, 500ms)
- Detection logic unchanged: RMS > 0.04 sustained 350ms still triggers
- Grace window 600ms unchanged

#### Files changed
- `src-tauri/src/voice/conversation.rs` — pre-roll buffer + drain-on-barge-in

#### Validation
- `cargo check` passes
- Manually verified: barge-in works, first words captured

### Whisper output script control (simplified vs traditional)

#### Problem
Whisper randomly outputs Traditional or Simplified Chinese for the same
audio. When the user's primary TTS voice is `zh-CN-*` (simplified), wake
word matching fails if Whisper outputs `zh-TW` characters (e.g. 同學 vs 同学).

#### Fix (three layers)
1. **`initial_prompt`** — Derived from the user's primary TTS voice:

| Primary voice | Whisper prompt | Output script |
|---------------|---------------|---------------|
| `zh-CN-*` | `以下是普通话的句子。` | Simplified |
| `zh-TW-*`, `zh-HK-*`, `zh-MO-*`, `ja-*` | `以下是繁體中文的句子。` | Traditional |
| Others | `以下是普通话的句子。` | Simplified (default) |

   Flow: `lib.rs` sets `TTS_PRIMARY_VOICE` env → `stt.rs` derives `--lang-prompt` →
   `stt-server.py` builds the `initial_prompt` string.

2. **`_t2s()` safety net** — `_clean_wake_text()` converts any remaining
   Traditional characters to Simplified via a compact mapping table (~80
   pairs). If the user's voice is `zh-TW`/`zh-HK`/`ja`, `_t2s()` is skipped
   to preserve traditional output.

3. **Hallucination filter** — Added `initial_prompt` text to
   `_HALLUCINATION_FRAGMENTS` and extended `_is_hallucination()` check to
   the `/transcribe` endpoint (previously only wake-word path had it).

#### Files changed
- `src-tauri/src/lib.rs` — set `TTS_PRIMARY_VOICE` env before `ensure_stt_server()`
- `src-tauri/src/voice/stt.rs` — derive `--lang-prompt` from voice prefix
- `src-tauri/resources/stt-server.py`:
  - New `--lang-prompt` argparse argument
  - `state.whisper_prompt` / `state.use_traditional` fields
  - `_transcribe_for_wake()` and `/transcribe` use `initial_prompt`
  - `_clean_wake_text()` calls `_t2s()` as safety net
  - New `_SIMP_TRAD_PAIRS` dict + `_t2s()` function
  - `_HALLUCINATION_FRAGMENTS`: added initial_prompt echo strings
  - `/transcribe` endpoint: added `_is_hallucination()` post-filter

### Silero VAD confirmation gate for barge-in

#### Problem
Barge-in detection used pure RMS energy (threshold 0.04, 350ms sustained).
Any sustained noise — whistles, claps, door slams, TV audio — could trip it,
cutting off TTS playback even though no human was speaking.

#### Fix
Added a Silero VAD confirmation step between RMS trigger and barge-in fire.
When RMS sustains above threshold, the pre-roll buffer (500ms of recent audio
at device sample rate) is flattened and sent to Silero VAD via the Python STT
server `/vad/check` endpoint. Only if Silero confirms human speech does the
barge-in actually fire.

- New `check_silero_vad_samples(samples, sample_rate)` — accepts raw samples
  at any rate, builds a WAV, POSTs to `/vad/check`
- `check_silero_vad()` refactored to delegate to the new function
- Both made `pub(crate)` so `conversation.rs` can call them

#### Files changed
- `src-tauri/src/commands/voice.rs` — refactored `check_silero_vad` →
  `pub(crate)`, added `check_silero_vad_samples`
- `src-tauri/src/voice/conversation.rs` — VAD gate in Speaking branch before
  barge-in fire

- `cargo check` passes (zero warnings)

### Fix: barge-in leaks audio queue slots (PA freezes after interrupt)

#### Problem
`stop_audio_queue()` (called on barge-in) stopped audio playback and reset the
queue counter, but did NOT stop the in-flight SSE stream. The old turn kept
receiving LLM tokens and calling `speak_internal`, reserving queue slots for
a generation that would never play. These slots were never released (generation
mismatch → early return in `audio_queue_release`), so the queue filled to
MAX_AUDIO_QUEUE (10) and the next turn's TTS blocked for 30s then dropped —
PA went silent.

#### Fix
`stop_audio_queue()` now also bumps `TURN_GENERATION`, causing the in-flight
SSE loop to detect supersession on the next token and exit immediately,
stopping the slot leak at the source.

#### Files changed
- `src-tauri/src/commands/chat.rs` — added `TURN_GENERATION.fetch_add(1)` in
  `stop_audio_queue()`

#### Validation
- `cargo check` passes (zero warnings)
