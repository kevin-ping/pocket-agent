# Pocket Agent v0.2.7

**Release Date**: 2026-06-07

Voice interaction overhaul: continuous conversation, wake-word detection, speaker verification, and audio UX polish. This is the biggest feature release since the initial launch.

## Highlights

### Continuous conversation mode
- **VAD-based turn detection** - Silero VAD detects when you stop speaking, no need to press the hotkey to stop recording
- **Configurable silence timeout and mic sensitivity** - fine-tune pause tolerance and noise floor in Settings
- **Seamless multi-turn flow** - the mic re-arms automatically after the agent finishes speaking, so you can keep talking without touching the keyboard
- **Unified pipeline** - single-shot and continuous modes share the same VAD + conversation state machine

### Wake word and speaker verification
- **3-gate wake pipeline** - Silero VAD (threshold 0.7) to 3dspeaker voiceprint embedding (cosine similarity >= 0.65) to MFCC+DTW keyword template match (distance <= 3.5)
- **MFCC+DTW over mel-spectrogram** - mel spectrograms compress into a single vector losing temporal nuance (same speaker saying different words scores 0.96+). MFCC preserves frame-by-frame trajectory, DTW provides elastic time-alignment with 14.6x discrimination factor
- **Speaker enrollment** - record a 3-second wake phrase to generate voiceprint embedding (.bin) + MFCC wake fingerprint (.npy)
- **Training mode** - append pronunciation variants (up to 10) for accent flexibility
- **Configurable wake STT model** - separate WAKE_STT_MODEL (default: tiny) from main STT_MODEL (default: base) for speed vs accuracy trade-off
- **Forced wake language** - WAKE_LANGUAGE=zh prevents Whisper from hallucinating wrong languages on short utterances
- **Sliding window buffer** - 3-second audio window with 1-second overlap for continuous wake detection

### PA-owned Python venv
- **Decoupled from Hermes** - PA now bootstraps its own ~/.pocket-agent/venv/ on first launch, no longer depends on ~/.hermes/hermes-agent/venv/
- **Fixes NumPy ABI crash** - Hermes upgrades pinned numpy 2.4.3 which broke Intel-Mac PyTorch 2.2.2 (NumPy 1.x ABI). PA venv uses compatible versions
- **Progress events** - venv-setup-{started,progress,done,error,ready} events with i18n status in Settings UI
- **Requirements bundled** - requirements-stt.txt shipped inside the app bundle, includes edge-tts

### Audio UX
- **Startup sound** - app_start.mp3 plays when all backend services are ready (health probe confirmed)
- **Prompt sound** - user_input.mp3 plays on state transitions: listening start, transcription complete
- **Listening avatar skin** - user_input.gif animated avatar shown during voice input
- **App-ready event** - backend emits app-ready only after STT health check passes, preventing premature startup sound
- **Reverb-processed audio** - both prompt and startup sounds have subtle reverb applied via ffmpeg

### TTS improvements
- **Response-language detection** - TTS voice now matches the response content language (not user input language), enabling cross-language conversations (e.g., ask in Chinese, get Japanese reply with Japanese voice)
- **Streaming command filter** - [CMD:...] and [LOCAL_CMD ...] markers hidden from chat display, announced as running command status via TTS

## Configuration

New .env keys:

- STT_MODEL=base (Whisper model for voice input)
- WAKE_STT_MODEL=tiny (Whisper model for wake-word detection)
- WAKE_LANGUAGE=zh (Force wake-word language)

## Known limitations
- sherpa-onnx ORT backend requires macOS 14+ on Apple Silicon; Intel Mac uses Python-only speaker verification
- Whisper tiny for wake detection may hallucinate on very short (< 1s) utterances; WAKE_LANGUAGE mitigates this
- 3-second wake buffer introduces ~3s latency between wake phrase and detection - this is by design (audio window needs enough content)

### UI language selection
- **Language dropdown in Settings** - select UI display language (English, 中文, 日本語, 한국어, Français, Deutsch, Español)
- **Default English** - UI defaults to English; no Auto/follow-voice option
- **Full i18n coverage** - all hardcoded labels in SettingsPanel replaced with i18n translations
- **tLang() / convLabelsLang()** - new functions that take lang key directly, used across 6 components
- **Unified dropdown styling** - language select uses same field-input style as other Settings dropdowns
