# Pocket Agent v0.3.1

**Release Date**: TBD

## Highlights

### Windows support (experimental)
- Pocket Agent now builds and runs on Windows 10/11 (x64) from source with `npm run tauri dev`, against a native Windows Hermes. Text chat, dictation, spoken replies, wake word and voiceprint, and desktop control through Hermes `computer_use` work. There is no installer yet. Setup: [docs/windows-install.md](../docs/windows-install.md).
- The global hotkey behaves as on macOS: press to start, press again to stop, double-click mode, Esc to cancel, and key capture in Settings. Saved hotkeys keep their format.
- The voice environment is built in `%USERPROFILE%\.pocket-agent\venv` from a 64-bit Python 3.10–3.12, found through the `py` launcher, a python.org install or `PATH`. The Microsoft Store placeholder and 32-bit Pythons are skipped.
- Prompts sent to Hermes name the machine as a "Windows PC", and the pocket-agent skill explains how to open a page on Windows.
- A recording of pure silence (wrong input device, muted, or blocked by Windows privacy settings) is reported with the fix instead of being transcribed or shown as a generic wake-service error.

### Voice activity detection on new installs
- Fixed voice activity detection failing on every call in a newly built voice environment, on macOS and Windows. silero-vad 6 no longer installs torchaudio, which its audio reader needs. Without VAD, silent recordings went to Whisper and barge-in had no speech check. The voice service now reads audio itself.

### Sharper avatar on standard-DPI screens
- The mesh avatar no longer looks blurred on displays at 100% scaling (most Windows PCs and non-Retina monitors). It is rendered at twice the size and scaled down.

### Upgrading from an earlier version
- `npm run dev` and `npm run build` now check that `node_modules` matches `package-lock.json` first. After a `git pull` that adds or bumps a dependency, they stop with the package names and "run npm install first", instead of vite failing later on an unresolved import.
- The README has a new **Updating** section: `git pull && npm install && npm run tauri dev`. The Python voice environment updates itself on the next start.

### Wake word on macOS older than 13.4
- Wake word and voiceprint now work on macOS 12 and 13.0–13.3. These systems get sherpa-onnx 1.10.46 from PyPI (1.12.26 needs macOS 13.4), and the wake phrase is converted to pronunciations by Pocket Agent itself, so both versions behave the same.
- The background download of a separate wake-engine build from this project's GitHub Release is gone. That build was never published, so on older macOS the download always failed. Pocket Agent now downloads nothing from outside PyPI for the wake word.

### Voice service left over from an earlier run
- Fixed speech recognition failing with "500 Internal Server Error" right after start, then falling back to a slow one-off transcriber. When Pocket Agent was killed (for example by `npm run tauri dev` restarting it), its voice service kept running with a log output nobody read, and every transcription failed. The voice service now ignores a broken log output.
- On start, Pocket Agent replaces a voice service left behind by an earlier run instead of reusing it, so it always runs the current code and settings. It only stops that process after checking it is the one listening on port 8651.

### Phone terminal: wake word with the screen off
- Saying the wake word to a phone with its screen off now works. The phone turns its screen on and shows Pocket Agent over the lock screen, so you can talk without unlocking. Before, nothing happened: Android pauses the hidden page that runs the conversation.
- During a conversation the screen stays on: the wake word and each reply keep it on for 3 more minutes, then the lock screen returns and the screen turns off as usual. Plugged in, it stays on as before.
- Only the owner's voice wakes the phone, and only while the phone is the one listening; with Pocket Agent on the Mac, the phone stays dark.

### Phone terminal: one phone, several computers
- Pair the phone with each computer running Pocket Agent by QR code: on the computer open Settings → Devices → Add phone, then on the phone tap Scan to add device and scan. Then switch between paired computers from the phone's device list.
- The phone serves one computer at a time. While one uses it, the others are refused — whether you ask from the other computer ("switch to the phone") or tap it on the phone — until the first one moves back to its desk, you disconnect on the phone, or it has been offline for 90 seconds.
- Saying "switch to the phone" to a computer that is not on the phone now reaches the phone over the network and opens that computer's page there, if the app is on screen. When the phone is busy, Pocket Agent says which computer is using it.
- Each computer keeps its own conversation history: switching computers switches context too.
- Settings → Devices on the computer lists the paired phones and removes them; a removed phone is disconnected at once and has to pair again. The computer stores only a hash of each phone's token.
- The QR code carries a one-time secret that never travels over the network: the phone and the computer prove to each other that they hold it. A code works for one phone, expires after 2 minutes, is replaced when you click Add phone again, and stops working after 5 wrong attempts. The phone saves nothing unless the computer proves it showed the code.
- Settings → Devices is available in all seven settings languages.
- The phone app follows the phone's system language in the same seven languages (English, Chinese, Japanese, Korean, French, German, Spanish); other languages show English. This covers the device list, the scanner, dialogs and the notification.
- A new scanner page: a viewfinder with a scan line over a dimmed camera view; only a code inside the viewfinder is read, and a vibration plus a short pause confirm it before pairing starts. Then comes a pairing screen, and a failure screen that says what went wrong (expired code, computer not reachable, …) with Scan again instead of a short pop-up.
- The phone app now has the Pocket Agent icon on the home screen and at the top of the device list.
- Computers do not announce themselves on the network. When a paired computer gets a new network address, show its QR code again and scan: the phone updates that computer's entry.

## Upgrading
- Run `npm install` after pulling.
- If speech recognition fails right after upgrading, a voice service from the old version may still be running: run `kill $(lsof -tiTCP:8651 -sTCP:LISTEN)` and restart Pocket Agent. This is needed once only.
- On macOS older than 13.4, restart Pocket Agent once while online: the voice environment switches to sherpa-onnx 1.10.46 by itself.
- Phone terminal: rebuild and reinstall the Android app (`cd android && ./gradlew assembleDebug && adb install -r app/build/outputs/apk/debug/app-debug.apk`) for the screen-off wake word.
- Phone terminal with several computers: rebuild and reinstall the Android app (same command as above). Your existing computer stays in the list, nothing to re-enter. Pair each additional computer once by scanning its QR code. A phone app built before QR pairing can no longer pair new computers (the 6-digit code is gone); computers it has already paired keep working.
- Windows as a phone-terminal computer: allow inbound TCP 8650 on the private network in Windows Firewall (see [docs/windows-install.md](../docs/windows-install.md)). UDP 5353 is no longer needed.
