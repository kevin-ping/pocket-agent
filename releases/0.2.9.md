# Pocket Agent v0.2.9

**Release Date**: TBD

Wake-word recognition accuracy improvements — borrowed techniques from 白龙马 (BaiLongma) voice project.

## Highlights

### Step 1: Whisper hallucination filtering
- **Hallucination word bank** — 30 common Whisper hallucination fragments (Chinese + English), including video platform catchphrases ("字幕", "感谢观看", "amara.org", etc.)
- **6 filter rules** — pure punctuation, single-char, known fragment match, single-char repetition (≥5 chars, ≤2 unique), timestamp/digit patterns, phrase-level repetition
- **Wake transcription only** — filter applies to `_transcribe_for_wake()` only; `/transcribe` conversation pipeline is untouched

### Step 2: VAD threshold tuning
- **Rust energy-VAD onset threshold** 0.015 → 0.010 — catches quieter wake words
- **Threshold cap** 0.03 → 0.02 — maintains sensitivity in moderate noise
- **Utterance peak gate** (new) — `MIN_UTTERANCE_PEAK_RMS=0.015`: buffers with peak RMS below threshold are discarded before sending HTTP, filtering noise that passes onset detection
- **Minimum send duration** 0.8s → 0.5s — "星引" (~0.5s) no longer truncated
- **Silero VAD threshold** (Python wake/check) 0.7 → 0.5 — shorter wake words no longer rejected as non-speech

## Bug fixes (post-release testing)

### STT server VAD pre-check crash — missing audio backend
`torchaudio>=2.1` macOS wheels ship no built-in audio decode backend. Without an
explicit `soundfile` dependency, `silero-vad`'s `read_audio()` failed with
`Couldn't find appropriate backend to handle uri ... and format None`, logged on
every `/transcribe` call and silently breaking VAD-gated silence detection
(`/vad/check`) and wake-word confirmation (`/wake/check`) — both always fell back
to "no speech detected".
- **Fix**: added `soundfile>=0.12.1` to `requirements-stt.txt`.

### Chat text streaming fell behind — and then skipped content — during TTS playback
The chat panel's per-character typewriter runs at a fixed ms/char pace unrelated
to real TTS speech duration, so on longer replies the displayed text could still
be mid-sentence after PA finished speaking.
- **Fix**: on `chat-audio-done`, immediately flush any buffered typewriter text
  (`chatStore.finishTypewriterNow()`) so text never lags behind audio.

That flush exposed a deeper backend bug: for multi-sentence replies,
`chat-audio-done` fired once per *sentence* instead of once per *turn* — the
"is this the last audio" check keyed off a `generation` value shared by every
sentence in the turn, so it was true after each one. Combined with the
unconditional flush above, this fragmented long replies: the chat box showed the
first sentence, then jumped straight to the last few words, dropping everything
in between. It also meant `notify_conversation_tts_done` (continuous-conversation
mode) could fire after just the first sentence.
- **Fix**: replaced the generation-based check with an explicit non-silent-sentence
  counter (`PENDING_NON_SILENT` + `SUBMISSION_DONE`, dedup'd via
  `AUDIO_DONE_EMITTED_GEN`) so `chat-audio-done` fires exactly once, when the true
  last sentence of the turn finishes playing.

### Files changed
- `src-tauri/resources/requirements-stt.txt` — added `soundfile>=0.12.1`
- `src-tauri/src/commands/chat.rs` — replaced `LAST_NON_SILENT_GEN` with
  `PENDING_NON_SILENT` / `SUBMISSION_DONE` / `AUDIO_DONE_EMITTED_GEN` +
  `begin_audio_submission()` / `maybe_emit_audio_done()` helpers; wired through

- `src/lib/stores/chat.ts` — added `chatStore.finishTypewriterNow()`
- `src/App.svelte` — `chat-audio-done` handler calls `finishTypewriterNow()`

  `settings.html`.
- Added left-side category navigation for General, Avatar, Voice, Conversation,
  Interruption, and Wake word settings.
- Opening Settings focuses the existing window instead of creating duplicates;
  closing it no longer resizes or moves the PA widget.
- Added a fixed action footer, independently scrolling content, unsaved-change
  confirmation, and working Save/Cancel behavior.
- Fixed the initial loading screen, native range-slider value synchronization,
  viewport overflow, and the window-close permission.

### Voice selection and preview
- Restored the complete legacy voice list (29 voices).
- Added a preview action beside each primary and secondary voice selector.
- Preview text is localized for Chinese, English, Japanese, Korean, French,
  German, and Spanish so each voice receives text it can pronounce.
- Preview playback uses the selected output format and volume without emitting
  normal chat playback events.
- Kept the preview control width stable while playback is active to prevent the
  selector layout from shifting.

### Runtime synchronization and localization

  window reloads the canonical configuration after each successful save.
- Runtime hotkey, double-click recording, wake-word, conversation, interruption,
  voice, avatar, and UI-language behavior is refreshed from the saved config.
- Added complete settings resources for Chinese, English, Japanese, Korean,
  French, German, and Spanish, including validation, recording, training, error,
  accessibility, and confirmation text.

## Barge-in pre-roll buffer (from Hermes 0.20.0)

### Problem
When the user interrupted PA mid-speech, the first few words were lost —
the RMS-based detector needed 350ms of sustained audio before firing, by
which point the opening syllable was gone.

### Fix
Added a pre-roll ring buffer (`VecDeque<Vec<i16>>`) in the Speaking branch
of the conversation state machine. Audio is continuously captured during
TTS playback; on barge-in trigger, the buffered audio is drained into the
utterance buffer so the user's first words are preserved.

- Max buffer duration: 500ms (`BARGE_IN_PREROLL_MAX_MS`)
- Memory overhead: ~48KB (16kHz mono, 500ms)
- Detection logic unchanged: RMS > 0.04 sustained 350ms still triggers
- Grace window 600ms unchanged

### Files changed
- `src-tauri/src/voice/conversation.rs` — pre-roll buffer + drain-on-barge-in

### Validation
- `cargo check` passes
- Manually verified: barge-in works, first words captured

## Whisper output script control (simplified vs traditional)

### Problem
Whisper randomly outputs Traditional or Simplified Chinese for the same
audio. When the user's primary TTS voice is `zh-CN-*` (simplified), wake
word matching fails if Whisper outputs `zh-TW` characters (e.g. 同學 vs 同学).

### Fix (three layers)
1. **`initial_prompt`** — Derived from the user's primary TTS voice:

| Primary voice | Whisper prompt | Output script |
|---------------|---------------|---------------|
| `zh-CN-*` | `以下是普通话的句子。` | Simplified |
| `zh-TW-*`, `zh-HK-*`, `zh-MO-*`, `ja-*` | `以下是繁體中文的句子。` | Traditional |
| Others | `以下是普通话的句子。` | Simplified (default) |

   Flow: `lib.rs` sets `TTS_PRIMARY_VOICE` env → `stt.rs` derives `--lang-prompt` →
   `stt-server.py` builds the `initial_prompt` string.

2. **`_t2s()` safety net** — `_clean_wake_text()` converts any remaining
   Traditional characters to Simplified via a compact mapping table (~80
   pairs). If the user's voice is `zh-TW`/`zh-HK`/`ja`, `_t2s()` is skipped
   to preserve traditional output.

3. **Hallucination filter** — Added `initial_prompt` text to
   `_HALLUCINATION_FRAGMENTS` and extended `_is_hallucination()` check to
   the `/transcribe` endpoint (previously only wake-word path had it).

### Files changed
- `src-tauri/src/lib.rs` — set `TTS_PRIMARY_VOICE` env before `ensure_stt_server()`
- `src-tauri/src/voice/stt.rs` — derive `--lang-prompt` from voice prefix
- `src-tauri/resources/stt-server.py`:
  - New `--lang-prompt` argparse argument
  - `state.whisper_prompt` / `state.use_traditional` fields
  - `_transcribe_for_wake()` and `/transcribe` use `initial_prompt`
  - `_clean_wake_text()` calls `_t2s()` as safety net
  - New `_SIMP_TRAD_PAIRS` dict + `_t2s()` function
  - `_HALLUCINATION_FRAGMENTS`: added initial_prompt echo strings
  - `/transcribe` endpoint: added `_is_hallucination()` post-filter
